# Context Hint：设计访谈记录

本文件记录设计访谈中用户已确认的选择，不代表功能已实现或验收通过。
它是正式 spec 的输入；正式规格已发布为 [ZepPellN/dsh-TUI#1](https://github.com/ZepPellN/dsh-TUI/issues/1)，[Context Hint spec](context-hint-spec.md) 为对应的 Git 工作副本。规格待用户审阅，实施 tickets 尚未发布。

## 已确认决定

1. **面向人而非自动记忆。** 三层卡片帮助用户重新掌握上下文，不自动注入主模型，也不替代真实会话记录或验证证据。
2. **按项目首次开启。** 用户首次手动开启后，每次交互结束在后台自动更新；失败与取消如实记录，不阻塞输入。恢复会话但没有新内容时不重复请求。
3. **共享与隔离。** 同一仓库的 worktree 共享 Project Card；Session Card 与 Turn Card 按会话隔离。模型只能提出 Project Suggestion，经过用户确认才能修改共享项目摘要。
4. **最小持久化。** 本地保存项目和各会话的最新卡片，重启后可查看；默认不额外保存摘要历史、原始 prompt 或工具输出副本，并提供删除入口。首次开启时说明选定会话内容会发送给摘要模型服务。
5. **独立的摘要模型选择。** 默认继承当前会话模型，也允许单独指定；绝不修改主会话模型。指定模型不可用时明确报错，不静默切换模型。
6. **有界调用与显式失败。** 每轮最多一次自动摘要请求，并限制输入、输出和等待时间；失败保留 Last Valid Card 并标记失败，不自动重试或修复，允许手动重试和暂停自动摘要。
7. **轻量展示。** 默认折叠为一句“当前进展 → 下一步”，Alt+O 展开三层卡片；快捷键可配置，提供命令入口。后台更新不抢焦点、不打断输入、不改变滚动位置。
8. **避免重复自动摘要。** Context Hint 开启期间不再同时触发旧的自动 recap，手动 /recap 保留；关闭 Context Hint 后恢复原有自动 recap 设置。
9. **首版验收范围。** session/worktree 切换及迟到请求不能串卡片；重启、恢复、fork、rewind 不得展示错误的完成状态；失败、取消、缺字段或非法响应不得崩溃或抹掉有效卡片。打包后在隔离 profile 中真实启动，并通过 macOS/Linux 验证；PR、integration 和 main 的 CI 都有明确检查。
10. **回退与分叉后的失效。** rewind 后隐藏不再适用的 Session/Turn 卡片并显示“待更新”，不假装还原未保存的历史摘要；fork 的新会话不盲目继承父会话的完成状态。Project 卡片不随单个会话回退。只在手动刷新或下一轮交互结束时重新生成，不因 rewind/fork 自动新增模型调用。
11. **隔离验收。** CI 使用真实 Harness、打包后的插件和隔离 profile，在外部模型调用边界使用确定性测试服务，不使用用户真实凭证、不产生付费模型调用。真实模型冒烟与替换用户现用 TUI/CLI 安装需另行授权。

## 设计访谈结论

用户已依次确认以上 11 项决定，设计访谈收束。下一阶段先审阅正式 spec，再通过 to-tickets 确认拆票粒度和依赖；implement-spec 等用户批准后启动。
